# 플레이 스토어 등록 안내 — 행복한 눈꽃마을 이야기

이미 Play Console에 다른 앱을 출시해 보신 분을 위한 순서표예요. 이 게임만의 특별한 점(서명 키, 테스트 앱의
저장 기록, 12명 테스트, Android 개발자 인증)에 집중했어요. 메뉴 이름은 Play Console 화면 기준이고, 화면 문구가 조금
다르면 비슷한 이름을 찾으세요. 이 문서와 화면 안내가 다르면 **화면이 맞아요**.

스토어 모습은 **힐링** 중심으로 새로 만들었어요(2026-10-27): 캐릭터 클로즈업 대신 여러 마을이 보이는 전경, 스노볼
아이콘, 주민들이 저마다의 하루를 보내는 스크린샷 8장, "내가 만든 작은 세상" 글.

이 폴더(`docs/store/`)에 있는 것:

| 파일 | 내용 |
|---|---|
| `upload_bundle/` | **올릴 그림만 순서대로 모은 폴더** (아이콘 → 그래픽 이미지 → 스크린샷 01~08) + 같은 내용의 zip |
| `크롬클로드_2단계_스토어등록정보.md` | 크롬 Claude에게 붙여 넣는 부탁 글: 스토어 글·그림·카테고리 채우기 (6단계) |
| `크롬클로드_3단계_앱콘텐츠.md` | 크롬 Claude에게 붙여 넣는 부탁 글: 앱 콘텐츠 설문 채우기 (7단계) |
| `listing_ko.md`, `listing_en.md` | 앱 이름, 간단한 설명, 자세한 설명, 출시 노트, 카테고리, 연락처, 그래픽 표 |
| `privacy_ko.html`, `privacy_en.html` | 개인정보처리방침 (인터넷에 올려서 주소를 넣어요) |
| `console_answers_ko.md` | 앱 콘텐츠 설문(데이터 보안, 콘텐츠 등급, 타겟층, 광고 등) 답과 이유, 코드 근거 |
| `assets/` | 아이콘, 그래픽 이미지(+ 다른 안 `options/`), 스크린샷 세 벌, 휴대폰 홈 화면 아이콘 세트 `launcher/`, 확인용 미리보기 `preview_*.jpg` (예전 그림과 나란히) |
| `tools/` | 위 그림·글자 수·부탁 글을 다시 만드는 도구 (Claude용) |

## 먼저 — 이 계정은 「12명 · 14일 비공개 테스트」를 해야 해요

디자이너님은 예전 앱을 낼 때 **앱마다 「프로덕션 액세스 신청」**을 하셨어요. 그러니 이 개발자 계정은 이 규칙
대상(2023년 11월 13일 이후에 만든 개인 계정)이고, 이 게임도 **새 앱이라 처음부터 다시** 해야 해요.

**순서**: 내부 테스트(디자이너님 휴대폰, 8단계) → **비공개 테스트**(테스터 12명 이상이 **14일 연속** 참여, 9단계)
→ 대시보드의 **「프로덕션 액세스 신청」** → 승인 후 정식 출시. 14일 동안에도 고친 버전을 올릴 수 있어요.

**테스터는 예전 앱 때의 이메일 목록을 다시 써요.** Play Console의 테스터 이메일 목록은 앱이 아니라 개발자 계정에
저장되어서, 새 앱의 비공개 테스트 화면에서 예전 목록을 그대로 골라 쓸 수 있어요. 다만 목록에 있다고 끝이 아니라,
테스터 한 명 한 명이 **이 앱의 새 참여 링크**를 열어 「테스터 되기」를 누르고 설치해야 수에 들어가요(예전 앱의
참여는 이 앱에 이어지지 않아요). 중간에 빠지는 사람이 있을 수 있으니 **15명 이상**에게 보내는 것을 추천해요.

(참고: 조직 계정으로 바꾸면 이 테스트가 필요 없지만, D-U-N-S 번호 등 확인에 몇 주가 걸려서 이번 출시에는 맞지
않아요. 이번엔 비공개 테스트로 가요.)

## 1. 계정 — 확인 끝

이 계정은 12명 · 14일 규칙 대상이에요(위 「먼저」). 따로 확인할 것은 없어요. 9단계는 비공개 테스트 길로 가요.

## 2. 앱 만들기

Play Console → **모든 앱 → 앱 만들기**
- 앱 이름: `행복한 눈꽃마을 이야기`
- 기본 언어: **한국어 – ko-KR**
- 앱 또는 게임: **게임**
- 무료 또는 유료: **무료** (나중에 유료로 바꿀 수 없어요)
- 선언 두 개(개발자 프로그램 정책, 미국 수출 법규)에 체크 → 만들기

패키지 이름(`com.snowbloom.village`)은 **첫 AAB를 올릴 때** 정해져요. 지금 테스트 앱과 같은 이름이어야 업데이트로 이어져요. 혹시 "이미 사용 중인 패키지 이름"이라고 나오면 업로드를 멈추고 Claude에게 알려 주세요.

이 단계는 선언 체크가 있어서 크롬 Claude에게 맡기지 말고 디자이너님이 직접 해 주세요.

## 3. 앱 서명 키 — ⚠ 첫 AAB를 올리기 **전에** 정해야 해요

Play는 앱을 **Play 앱 서명**으로 배포해요. 이용자 휴대폰에 가는 앱은 「앱 서명 키」로 서명돼요. 첫 버전을 올리면 그때 정해진 키는 사실상 바꿀 수 없어요.

### 추천: 지금 테스트 키를 그대로 「앱 서명 키」로 쓰기

| | 지금 테스트 키 사용 (추천) | Google이 새 키 만들기 (기본값) |
|---|---|---|
| 휴대폰에 깔린 테스트 앱 | Play 버전이 **그 위에 업데이트**로 설치돼요 | 서명이 달라서 Play 버전을 설치하려면 **테스트 앱을 지워야** 해요 |
| 지금까지의 긴 저장 기록 | **그대로 남아요** | **사라져요** (게임에 저장 내보내기 기능이 없어서 옮길 방법이 없어요) |
| 할 일 | PEPK 파일 2개를 받아 Claude에게 보내고, Claude가 만든 파일 1개를 올리기 (아래) | 버튼 하나 |
| 주의 | 테스트 키가 이제 **진짜 열쇠**가 돼요. 보관용 zip(`snowbloom-앱열쇠-보관용.zip`)과 키 파일(`snowbloom-test.p12`)은 안전한 곳에 두고 **아무에게도 주지 마세요**(이 키로 서명된 APK를 주는 것은 괜찮아요 — APK에는 공개 인증서만 들어 있어요). 키 파일은 공개 저장소에 올라가지 않게 막혀 있어요(`dist/`는 git에서 빠짐). 다만 이 테스트 키의 **비밀번호는 처음부터 공개 저장소의 빌드 도구에 적혀 있어서**, 키 파일을 가진 사람은 누구나 쓸 수 있어요. 그래서 첫 업로드 전에 Claude가 같은 키를 **새 비밀번호로 다시 포장**해 두는 것을 추천해요(키와 인증서는 그대로라 Play·휴대폰에는 아무 변화가 없어요). 인증서 이름에 "TEST ONLY"라는 글자가 들어 있는데, 이용자에게는 보이지 않고 동작에도 영향이 없어요. | 없음 |

**순서 (추천 방법)**
1. 앱을 만든 뒤 **테스트 및 출시 → 앱 무결성**(또는 **출시 → 설정 → 앱 서명**)으로 가요. 첫 버전을 만들기 전 화면에서 **「앱 서명 키 변경」**(또는 「다른 키 사용」)을 누르세요.
2. **「Java 키 저장소에서 키 내보내기 및 업로드」**(PEPK 도구 사용)를 고르세요.
3. 화면 안내에 있는 두 가지를 내려받아 Claude에게 보내 주세요:
   - **PEPK 도구** (`pepk.jar`)
   - **암호화 공개 키** (`encryption_public_key.pem` 같은 이름. 예전 화면에서는 파일 대신 긴 영문·숫자 문자열이 보여요 — 그 문자열을 복사해 보내 주세요)
   두 가지 모두 비밀이 아니에요(공개 키예요). 화면에 보이는 **명령어 예시**도 캡처해서 같이 보내 주시면 좋아요.
4. Claude가 테스트 키를 그 공개 키로 **암호화한 파일**(`snowbloom-app-signing-key.zip`)을 만들어 드려요. 구글만 열 수 있게 잠긴 파일이라 메신저로 받아도 안전해요.
5. 같은 화면에서 그 파일을 업로드해요.
6. **「(권장) 보안 강화를 위해 새 업로드 키 만들기」** 칸에 Claude가 만든 **업로드 키 인증서**(`snowbloom-upload-certificate.pem`)를 **꼭** 올려요(4단계). Claude가 만드는 AAB는 모두 이 업로드 키로 서명되기 때문에, 이 칸을 건너뛰면 Play가 테스트 키를 업로드 키로도 쓰게 되어 AAB 업로드가 "잘못된 키로 서명됨"으로 거절돼요. 이 칸이 안 보이면 저장하지 말고 화면을 캡처해서 Claude에게 보내 주세요.
7. 저장하면 **앱 서명 키 인증서**와 **업로드 키 인증서**의 지문(SHA-256)이 보여요. 이 두 줄을 캡처해서 Claude에게 보내 주세요. 앱 서명 키 지문이 아래와 같으면 성공이에요:
   `B1:D3:10:4B:7A:CD:29:31:06:1D:2B:96:FA:FD:0C:5C:C5:29:36:14:1B:B5:B5:F0:62:18:D5:D3:4C:D5:7D:AF`

### 다른 길: Google이 새 키 만들기
2번에서 바꾸지 않고 그대로 첫 버전을 올리면 Google이 키를 새로 만들어요. 간단하지만, 그러면 **휴대폰의 테스트 앱을 지우고** Play에서 새로 설치해야 하고 **저장은 처음부터** 시작해요. 저장을 꼭 살리고 싶으면 이 길은 고르지 마세요.

## 3-1. Android 개발자 인증 — 패키지 이름과 서명 인증서 등록

Google은 앞으로 Android 휴대폰에 설치되는 앱이 **인증된 개발자에게 등록된 앱**이어야 설치되게 바꾸고 있어요
(Play 밖에서 받은 APK도 포함). Play Console의 **「Android 개발자 인증」** 페이지에서 이 게임의 패키지 이름과
서명 인증서를 등록해 두면, Play 버전뿐 아니라 Claude가 보내 드리는 **테스트 APK**도 계속 설치할 수 있어요.

1. Play Console 왼쪽 메뉴(앱 목록 화면)의 **「Android 개발자 인증」**(또는 **설정 → 개발자 계정 → Android 개발자 인증**)을 열어요.
   개발자 신원 인증이 아직이면 그 화면의 안내를 먼저 따라요(신분증·주소 확인 같은 단계는 디자이너님이 직접).
2. **앱(패키지 이름) 등록**: `com.snowbloom.village`
   - 첫 AAB를 Play에 올린 뒤에는 이 앱이 목록에 이미 있을 수 있어요. 있으면 3번만 확인해요.
3. **서명 인증서(SHA-256)**: 이용자 휴대폰에 가는 앱을 서명하는 키의 인증서를 등록해요.
   - 테스트 키 = (3단계 추천 방법을 따랐다면) Play의 앱 서명 키:
     `B1:D3:10:4B:7A:CD:29:31:06:1D:2B:96:FA:FD:0C:5C:C5:29:36:14:1B:B5:B5:F0:62:18:D5:D3:4C:D5:7D:AF`
   - 3단계에서 「Google이 새 키 만들기」를 골랐다면: Play의 앱 서명 키는 자동으로 들어가 있을 거예요. 위 테스트 키
     인증서를 **추가로** 등록해 두면 테스트 APK도 설치돼요.
   - 업로드 키 인증서는 넣지 않아도 돼요(이용자 휴대폰에 가는 앱을 서명하지 않아요). 화면이 요구하면 넣어도 괜찮아요.
4. 키를 가지고 있다는 **증명**(예: 화면이 준 글자를 넣고 그 키로 서명한 APK를 올리기)을 요구하면, 그 화면을 캡처해서
   Claude에게 보내 주세요. Claude가 그 APK를 만들어 드려요. 비밀번호나 키 파일은 보내지 않아도 돼요.
5. 등록이 끝나면 목록 화면(패키지 이름 + 인증서 지문)을 캡처해서 Claude에게 보내 주세요.

언제부터 꼭 필요한지: 2026년에는 브라질·인도네시아·싱가포르·태국부터 시작하고, 다른 나라는 그 뒤에 넓어진다고
발표됐어요(한국은 처음 나라에 없어요). 그래서 지금 당장 설치가 막히지는 않지만, 미리 해 두면 나중에 테스트 APK가
갑자기 안 깔리는 일이 없어요. (이 환경에서는 Google 고객센터 원문을 열 수 없어서 발표 요약으로만 확인했어요.
화면 안내가 이 문서와 다르면 **화면이 맞아요**.)

## 4. 업로드 키

업로드 키는 Claude가 AAB를 Play에 올릴 때 서명하는 열쇠예요(앱 서명 키와 따로). 잃어버리거나 새어 나가도 Play Console에서 **재설정을 요청**할 수 있어요.
- Claude가 새 업로드 키를 만들어 이 작업 공간의 비공개 폴더(`dist/`, git에서 빠짐)에 두고, 디자이너님께 **보관용 사본**과 **인증서 파일**을 따로 드려요.
- 3단계 6번에서 그 인증서를 등록해요.
- 비밀번호나 키 파일은 문서·채팅·저장소에 적지 않아요.

## 5. 개인정보처리방침 올리기

1. 방침 내용은 채워져 있어요(`privacy_ko.html`, `privacy_en.html`: 누리엔터테인먼트, 연락처, 시행일 2026-10-27). 바꿀 곳이 있으면 Claude에게 알려 주세요.
2. 인터넷 주소가 필요해요. 방법 하나를 고르세요:
   - **(추천) 작은 GitHub 저장소 + GitHub Pages**: 방침 두 파일만 담은 공개 저장소(예: `snowbloom-privacy`)를 만들고 Pages를 켜면 `https://<GitHub 아이디>.github.io/snowbloom-privacy/privacy_ko.html` 같은 주소가 생겨요. 지금 게임 저장소(`nurient`)는 2 GB가 넘어서 Pages로 통째로 올리기에 맞지 않아요. 「방침 페이지 올려 줘」라고 하시면 Claude가 만들어 드려요.
   - 사업자 홈페이지가 있으면 그 사이트에 두 파일을 올려도 돼요.
3. 주소를 브라우저(휴대폰 포함)에서 열어 보고, Play Console **앱 콘텐츠 → 개인정보처리방침**과 스토어 **연락처 → 개인정보처리방침**에 넣어요.

## 6. 스토어 등록정보 채우기 — 크롬 Claude와 함께 (`크롬클로드_2단계_스토어등록정보.md`)

그 문서의 부탁 글을 크롬 Claude에게 붙여 넣으면, 글·카테고리는 크롬 Claude가 채우고 **그림 파일을 고를 차례마다
디자이너님께 어떤 파일을 고를지 알려 줘요**(파일 고르기 창은 디자이너님이 직접). 연락처 이메일은 붙여 넣기 전에
그 문서의 빈칸에 직접 적어 주세요.

손으로 하실 때는 — **성장 → 스토어 등록정보 → 기본 스토어 등록정보**:

| 칸 | 넣을 것 |
|---|---|
| 앱 이름 | `listing_ko.md` → 앱 이름 (`행복한 눈꽃마을 이야기`) |
| 간단한 설명 | `listing_ko.md` → 간단한 설명 |
| 자세한 설명 | `listing_ko.md` → 자세한 설명 |
| 앱 아이콘 | `upload_bundle/1_app_icon_512.png` (스노볼, 512 × 512) |
| 그래픽 이미지 | `upload_bundle/2_feature_graphic_1024x500.png` (해안 마을 전경) |
| 휴대전화 스크린샷 | `upload_bundle/3_phone_screenshot_01.jpg` … `08.jpg` (1080 × 1920, 한국어 설명 띠) — 번호 순서대로 8장 |
| 태블릿 스크린샷 | 비워 두기 |
| 동영상 | 비워 두기 |

- 그림 고르기: 안마다 비교 그림이 있어요 — `assets/preview_icon_before_after.jpg`(아이콘 3안), `assets/preview_feature_before_after.jpg`(그래픽 이미지 3안), `assets/preview_screenshots_before_after.jpg`(예전 8장 / 새 8장). 다른 안을 쓰고 싶으면 `assets/options/`의 파일을 올리면 돼요.
- 글자 없는 스크린샷을 원하시면 `assets/screenshots/01…08.jpg`를 대신 올려요(한 세트만).

**영어**: 같은 화면 → **번역 관리 → 번역 직접 추가 → 영어(미국)** → `listing_en.md`, 그래픽 이미지는 `assets/feature_graphic_en.png`, 스크린샷은 `assets/screenshots_caption_en/` (2단계 문서 아래쪽의 「선택」 부탁 글).

**스토어 설정**(성장 → 스토어 등록정보 → 스토어 설정): 앱 카테고리 **게임 → 시뮬레이션**, 연락처 이메일. 태그는 나중에 골라도 돼요(`listing_ko.md`의 표).

## 7. 앱 콘텐츠 설문 — 크롬 Claude와 함께 (`크롬클로드_3단계_앱콘텐츠.md`)

**정책 및 프로그램 → 앱 콘텐츠**의 항목을 `console_answers_ko.md`의 답대로 채워요: 개인정보처리방침, 앱 액세스 권한,
광고, 광고 ID, 콘텐츠 등급, 타겟층, 데이터 보안, 정부 앱, 금융 기능, 건강, 뉴스. 3단계 문서의 부탁 글을 붙여 넣으면
크롬 Claude가 답을 고르고, **콘텐츠 등급 「제출」과 약관 동의 체크는 디자이너님께 넘겨요.** 개인정보처리방침 주소
칸은 비어 있는 채로 두었어요 — 5단계에서 주소가 생기면 채워 넣고 붙여 넣으세요(없으면 그 항목만 건너뛰어요).
대시보드의 「앱 설정」 목록이 모두 초록 체크가 되면 끝이에요.

## 8. 내부 테스트 — 디자이너님 휴대폰에 먼저

1. **테스트 및 출시 → 테스트 → 내부 테스트 → 테스터** 탭: 이메일 목록을 만들고 **디자이너님 휴대폰의 Play 스토어 구글 계정**을 넣어요.
2. **새 버전 만들기** → Claude가 보내 드린 `.aab` 파일 업로드 → 출시 노트(`listing_ko.md`) → 저장 → 검토 → 내부 테스트로 출시.
3. 테스터 탭의 **참여 링크(웹에서 참여)** 를 휴대폰에서 열고 「테스터 되기」 → Play 스토어 링크로 이동.
4. **휴대폰의 테스트 앱을 지우지 마세요.** 3단계를 추천 방법으로 했다면 Play에 **「업데이트」** 버튼이 보여요 → 누르면 저장이 그대로인 채로 Play 버전이 돼요. 그 뒤로는 Play가 자동으로 업데이트해 줘요.
   - 「업데이트」 대신 「설치」만 보이거나 "충돌"·"설치 안 됨"이 나오면 **누르지 말고** 화면을 캡처해서 보내 주세요(서명 확인이 필요해요).
5. 게임을 열어 저장이 이어지는지, 소리·진동·뒤로 가기(「게임을 끝낼까요?」)가 되는지 봐 주세요.

버전 번호: 휴대폰의 테스트 앱이 versionCode 4021이라, Play에 올리는 첫 버전은 **4022 이상**이어야 위로 업데이트돼요(Claude가 맞춰서 만들어요).

## 9. 비공개 테스트 (12명 · 14일) → 프로덕션 액세스 신청 → 정식 출시

1. **테스트 및 출시 → 테스트 → 비공개 테스트** → 트랙 만들기(기본 「Closed testing - Alpha」 그대로도 돼요) →
   **테스터** 탭 → 이메일 목록에서 **예전 앱 때 만든 테스터 목록**을 체크해요(목록에 없는 사람은 새로 추가).
   피드백 받을 이메일이나 주소를 묻는 칸이 있으면 연락처 이메일을 넣어요.
2. **새 버전 만들기** → 내부 테스트에서 확인한 버전을 **라이브러리에서 추가** → 출시 노트(`listing_ko.md`) → 검토 →
   비공개 테스트로 출시. 이때 「검토를 위해 보내기」를 누르는 것은 **디자이너님이 직접** 해요(크롬 Claude에게 맡기지
   않아요). 비공개 테스트의 첫 검토는 며칠 걸릴 수 있어요.
3. 승인되면 테스터 탭의 **참여 링크**를 테스터들에게 보내요. 한 명씩 링크를 열어 「테스터 되기」 → Play에서 설치.
   보내는 글 예: `새 게임 「행복한 눈꽃마을 이야기」 비공개 테스트에 참여해 주세요. 링크를 열어 「테스터 되기」를 누르고
   설치한 뒤, 14일 동안 지우지 말아 주세요. 가끔 열어 마을을 구경해 주시면 더 좋아요.`
4. **14일 연속**으로 12명 이상이 참여 상태여야 해요(중간에 빠지면 다시 세는 경우가 있어요). 대시보드에 참여 인원과
   날짜가 보여요. 그동안 Claude가 고친 버전을 올려도 괜찮아요.
5. 대시보드의 **「프로덕션 액세스 신청」** → 테스트가 어땠는지, 어떤 의견을 받아 무엇을 고쳤는지, 출시 준비가 되었다고
   보는 이유 같은 질문에 답해요. 예전 앱 때와 같은 질문이에요. 답 초안이 필요하면 Claude에게 말해 주세요.
6. 승인되면 **테스트 및 출시 → 프로덕션** → 국가/지역(대한민국, 원하면 더) → 새 버전 만들기 → 테스트한 버전을
   **라이브러리에서 추가** → 검토 → 출시. 처음엔 **단계적 출시**(예: 20%)도 고를 수 있어요.

## 10. 앞으로 업데이트

1. Claude가 새 버전 AAB를 만들어 드려요(버전 번호 +1, 같은 업로드 키로 서명).
2. 내부 테스트에 먼저 올려 휴대폰에서 확인 → 프로덕션으로 승격.
3. 출시 노트는 그 버전에서 바뀐 것만 짧게. 그림이나 기능이 많이 바뀌면 스크린샷도 새로 찍어 드려요.
   **말티푸 누리가 들어가는 버전**이 나오면: 스크린샷을 누리가 보이게 다시 찍고, 자세한 설명의 "마을 강아지"를
   "강아지 누리"로 바꿔요(`listing_ko.md` 「누리가 들어간 뒤」). 지금 8장에는 예전 강아지가 일부러 안 보이게 했어요.
4. 게임이 정보를 다루는 방식이 바뀌는 업데이트(구글 로그인, 클라우드 저장, 온라인 AI 수다, 광고, 결제)는 **먼저** 방침과 설문을 고쳐요 — `console_answers_ko.md` 맨 아래.
