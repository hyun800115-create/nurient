# 플레이 스토어 등록 안내 — 행복한 눈꽃마을 이야기

이미 Play Console에 다른 앱을 정식 출시해 보신 분을 위한 순서표예요. 이 게임만의 특별한 점(서명 키, 테스트 앱의
저장 기록, 12명 테스트 규칙)에 집중했어요. 메뉴 이름은 Play Console 화면 기준이고, 화면 문구가 조금 다르면 비슷한
이름을 찾으세요. 이 문서와 화면 안내가 다르면 **화면이 맞아요**.

이 폴더(`docs/store/`)에 있는 것:

| 파일 | 내용 |
|---|---|
| `listing_ko.md`, `listing_en.md` | 앱 이름, 간단한 설명, 자세한 설명, 출시 노트, 카테고리, 연락처 |
| `privacy_ko.html`, `privacy_en.html` | 개인정보처리방침 (인터넷에 올려서 주소를 넣어요) |
| `console_answers_ko.md` | 앱 콘텐츠 설문(데이터 보안, 콘텐츠 등급, 타겟층, 광고 등) 답과 이유, 코드 근거 |
| `assets/` | 아이콘, 그래픽 이미지, 스크린샷 (+ 확인용 미리보기 `preview_*.jpg`) |
| `tools/` | 위 그림과 글자 수를 다시 만드는 도구 (Claude용) |

## 먼저 — 「12명 · 14일 비공개 테스트」를 해야 하나요?

**사업자 등록이 있다는 것만으로는 정해지지 않아요.** 기준은 Play **개발자 계정의 종류**와 **만든 날짜**예요.

| 내 개발자 계정 | 12명·14일 비공개 테스트 | 바로 프로덕션 출시 |
|---|---|---|
| **조직(Organization) 계정** | 안 해도 돼요 | 가능 |
| **개인(Personal) 계정**, 2023년 11월 13일 **이전**에 만듦 | 안 해도 돼요 | 가능 |
| **개인 계정**, 2023년 11월 13일 **이후**에 만듦 | **해야 해요** — 테스터 12명 이상이 14일 연속 참여한 비공개 테스트 후 「프로덕션 액세스 신청」 | 테스트를 마친 뒤에만 |

- 사업자이시더라도 개발자 계정을 **개인**으로 만드셨다면 개인 계정 규칙을 따라요. 개인사업자는 개인 계정으로 가입한 경우가 많아요.
- 이미 다른 앱을 정식 출시하셨더라도, 개인 계정(2023-11-13 이후)이면 **새 앱마다** 이 테스트를 다시 해야 한다는 것이 일반적인 경험담이에요. 구글 공식 문구는 "앱에 대해 비공개 테스트를 진행해야 한다"이고, 앱마다인지에 대한 공식 문장은 이번에 직접 확인하지 못했어요. 아래 방법으로 화면에서 확인하는 것이 가장 확실해요.
- 다른 앱을 출시하실 때 12명 테스트를 하셨다면 → 개인 계정(2023-11-13 이후)일 가능성이 높아요. 테스트 없이 바로 출시하셨다면 → 조직 계정이거나 그 전에 만든 계정일 가능성이 높아요.

**확인하는 법 (1분)**
1. Play Console 왼쪽 아래 **설정(톱니바퀴) → 개발자 계정 → 계정 세부정보**(또는 「내 정보 / About you」): **계정 유형**이 「개인」인지 「조직」인지 보여요.
2. 새 앱을 만든 뒤(2단계) 앱 **대시보드**를 보세요. 「비공개 테스트 실행 — 테스터 12명 이상, 14일」, 「프로덕션 액세스 신청」 같은 단계가 보이면 규칙 대상이에요. 그런 단계 없이 「프로덕션」 트랙에 바로 버전을 만들 수 있으면 대상이 아니에요.

**개인 → 조직 계정으로 바꾸고 싶다면**: Play Console에서 계정 유형을 바꿀 수 있어요(개발자 계정 → 내 정보). 조직 이름·주소, 인증된 공식 웹사이트, **D-U-N-S 번호**, 조직용 결제 프로필이 필요하고 확인에 며칠~몇 주 걸릴 수 있어요(한국 사업자의 D-U-N-S는 보통 나이스디앤비에서 발급 — 확인 필요). 이번 출시를 위해 서두를 일은 아니고, 앞으로 앱을 계속 낼 사업자라면 고려할 만해요. 바꾸면 스토어에 개발자 이름·주소가 조직 정보로 보여요.

어느 경우든 **처음엔 「내부 테스트」로 디자이너님 휴대폰에 먼저 설치**해 보는 것을 추천해요(8단계). 내부 테스트는 12명 규칙과 상관없고 보통 몇 분 안에 열려요.

## 1. 계정 확인

위 「먼저」의 확인법대로 **계정 유형과 만든 날짜**를 보고 Claude에게 알려 주세요. 이에 따라 9단계가 달라져요.

## 2. 앱 만들기

Play Console → **모든 앱 → 앱 만들기**
- 앱 이름: `행복한 눈꽃마을 이야기`
- 기본 언어: **한국어 – ko-KR**
- 앱 또는 게임: **게임**
- 무료 또는 유료: **무료** (나중에 유료로 바꿀 수 없어요)
- 선언 두 개(개발자 프로그램 정책, 미국 수출 법규)에 체크 → 만들기

패키지 이름(`com.snowbloom.village`)은 **첫 AAB를 올릴 때** 정해져요. 지금 테스트 앱과 같은 이름이어야 업데이트로 이어져요. 혹시 "이미 사용 중인 패키지 이름"이라고 나오면 업로드를 멈추고 Claude에게 알려 주세요.

## 3. 앱 서명 키 — ⚠ 첫 AAB를 올리기 **전에** 정해야 해요

Play는 앱을 **Play 앱 서명**으로 배포해요. 이용자 휴대폰에 가는 앱은 「앱 서명 키」로 서명돼요. 첫 버전을 올리면 그때 정해진 키는 사실상 바꿀 수 없어요.

### 추천: 지금 테스트 키를 그대로 「앱 서명 키」로 쓰기

| | 지금 테스트 키 사용 (추천) | Google이 새 키 만들기 (기본값) |
|---|---|---|
| 휴대폰에 깔린 테스트 앱 | Play 버전이 **그 위에 업데이트**로 설치돼요 | 서명이 달라서 Play 버전을 설치하려면 **테스트 앱을 지워야** 해요 |
| 지금까지의 긴 저장 기록 | **그대로 남아요** | **사라져요** (게임에 저장 내보내기 기능이 없어서 옮길 방법이 없어요) |
| 할 일 | PEPK 파일 2개를 받아 Claude에게 보내고, Claude가 만든 파일 1개를 올리기 (아래) | 버튼 하나 |
| 주의 | 테스트 키가 이제 **진짜 열쇠**가 돼요. 보관용 zip(`snowbloom-앱열쇠-보관용.zip`)을 안전한 곳에 두고, 이 키로 서명한 APK를 다른 사람에게 주지 마세요. 키는 공개 저장소에 올라가지 않게 막혀 있어요(`dist/`는 git에서 빠짐). 인증서 이름에 "TEST ONLY"라는 글자가 들어 있는데, 이용자에게는 보이지 않고 동작에도 영향이 없어요. | 없음 |

**순서 (추천 방법)**
1. 앱을 만든 뒤 **테스트 및 출시 → 앱 무결성**(또는 **출시 → 설정 → 앱 서명**)으로 가요. 첫 버전을 만들기 전 화면에서 **「앱 서명 키 변경」**(또는 「다른 키 사용」)을 누르세요.
2. **「Java 키 저장소에서 키 내보내기 및 업로드」**(PEPK 도구 사용)를 고르세요.
3. 화면 안내에 있는 두 가지를 내려받아 Claude에게 보내 주세요:
   - **PEPK 도구** (`pepk.jar`)
   - **암호화 공개 키** (`encryption_public_key.pem` 같은 이름)
   두 파일 모두 비밀이 아니에요(공개 키예요). 화면에 보이는 **명령어 예시**도 캡처해서 같이 보내 주시면 좋아요.
4. Claude가 테스트 키를 그 공개 키로 **암호화한 파일**(`.zip`)을 만들어 드려요. 구글만 열 수 있게 잠긴 파일이라 메신저로 받아도 안전해요.
5. 같은 화면에서 그 파일을 업로드해요.
6. **「(권장) 보안 강화를 위해 새 업로드 키 만들기」** 칸이 있으면: Claude가 만든 **업로드 키 인증서**(`upload_certificate.pem`)를 올려요(4단계). 없으면 건너뛰어도 돼요 — 그때는 테스트 키가 업로드 키도 겸해요.
7. 저장하면 **앱 서명 키 인증서**와 **업로드 키 인증서**의 지문(SHA-256)이 보여요. 이 두 줄을 캡처해서 Claude에게 보내 주세요. 앱 서명 키 지문이 아래와 같으면 성공이에요:
   `B1:D3:10:4B:7A:CD:29:31:06:1D:2B:96:FA:FD:0C:5C:C5:29:36:14:1B:B5:B5:F0:62:18:D5:D3:4C:D5:7D:AF`

### 다른 길: Google이 새 키 만들기
2번에서 바꾸지 않고 그대로 첫 버전을 올리면 Google이 키를 새로 만들어요. 간단하지만, 그러면 **휴대폰의 테스트 앱을 지우고** Play에서 새로 설치해야 하고 **저장은 처음부터** 시작해요. 저장을 꼭 살리고 싶으면 이 길은 고르지 마세요.

## 4. 업로드 키

업로드 키는 Claude가 AAB를 Play에 올릴 때 서명하는 열쇠예요(앱 서명 키와 따로). 잃어버리거나 새어 나가도 Play Console에서 **재설정을 요청**할 수 있어요.
- Claude가 새 업로드 키를 만들어 이 작업 공간의 비공개 폴더(`dist/`, git에서 빠짐)에 두고, 디자이너님께 **보관용 사본**과 **인증서 파일**을 따로 드려요.
- 3단계 6번에서 그 인증서를 등록해요.
- 비밀번호나 키 파일은 문서·채팅·저장소에 적지 않아요.

## 5. 개인정보처리방침 올리기

1. `privacy_ko.html`과 `privacy_en.html`의 `{{ }}` 자리를 채울 정보(상호, 개인정보 보호책임자 이름, 이메일, 주소, 시행일)를 Claude에게 알려 주세요. Claude가 채워 드려요.
2. 인터넷 주소가 필요해요. 방법 하나를 고르세요:
   - **(추천) 작은 GitHub 저장소 + GitHub Pages**: 방침 두 파일만 담은 공개 저장소(예: `snowbloom-privacy`)를 만들고 Pages를 켜면 `https://<GitHub 아이디>.github.io/snowbloom-privacy/privacy_ko.html` 같은 주소가 생겨요. 지금 게임 저장소(`nurient`)는 2 GB가 넘어서 Pages로 통째로 올리기에 맞지 않아요. 「방침 페이지 올려 줘」라고 하시면 Claude가 만들어 드려요.
   - 사업자 홈페이지가 있으면 그 사이트에 두 파일을 올려도 돼요.
3. 주소를 브라우저(휴대폰 포함)에서 열어 보고, Play Console **앱 콘텐츠 → 개인정보처리방침**과 스토어 **연락처 → 개인정보처리방침**에 넣어요.

## 7. 앱 콘텐츠 설문

**정책 및 프로그램 → 앱 콘텐츠**의 항목을 `console_answers_ko.md` 순서대로 채워요: 개인정보처리방침, 앱 액세스 권한, 광고, 광고 ID, 콘텐츠 등급, 타겟층, 데이터 보안, 정부 앱, 금융 기능, 건강, 뉴스. 대시보드의 「앱 설정」 목록이 모두 초록 체크가 되면 끝이에요.

## 8. 내부 테스트 — 디자이너님 휴대폰에 먼저

1. **테스트 및 출시 → 테스트 → 내부 테스트 → 테스터** 탭: 이메일 목록을 만들고 **디자이너님 휴대폰의 Play 스토어 구글 계정**을 넣어요.
2. **새 버전 만들기** → Claude가 보내 드린 `.aab` 파일 업로드 → 출시 노트(`listing_ko.md`) → 저장 → 검토 → 내부 테스트로 출시.
3. 테스터 탭의 **참여 링크(웹에서 참여)** 를 휴대폰에서 열고 「테스터 되기」 → Play 스토어 링크로 이동.
4. **휴대폰의 테스트 앱을 지우지 마세요.** 3단계를 추천 방법으로 했다면 Play에 **「업데이트」** 버튼이 보여요 → 누르면 저장이 그대로인 채로 Play 버전이 돼요. 그 뒤로는 Play가 자동으로 업데이트해 줘요.
   - 「업데이트」 대신 「설치」만 보이거나 "충돌"·"설치 안 됨"이 나오면 **누르지 말고** 화면을 캡처해서 보내 주세요(서명 확인이 필요해요).
5. 게임을 열어 저장이 이어지는지, 소리·진동·뒤로 가기(「게임을 끝낼까요?」)가 되는지 봐 주세요.

버전 번호: 휴대폰의 테스트 앱이 versionCode 4021이라, Play에 올리는 첫 버전은 **4022 이상**이어야 위로 업데이트돼요(Claude가 맞춰서 만들어요).

## 9. 정식 출시

**A. 12명 규칙 대상이 아닌 계정 (조직, 또는 2023-11-13 이전 개인 계정)**
- **테스트 및 출시 → 프로덕션** → 국가/지역(대한민국, 원하면 더) → 새 버전 만들기 → 내부 테스트에서 확인한 버전을 **라이브러리에서 추가**(또는 내부 테스트 버전 「승격」) → 검토 → 출시.
- 새 앱의 첫 검토는 며칠 걸릴 수 있어요. 처음엔 **단계적 출시**(예: 20%)도 고를 수 있어요.

**B. 12명 규칙 대상 계정 (2023-11-13 이후 개인 계정)**
1. **비공개 테스트** 트랙을 만들고, 테스터(구글 계정 이메일) **12명 이상**을 넣어요. 가족·지인·다른 앱 테스터에게 참여 링크를 보내 「테스터 되기」를 누르고 설치하게 해요.
2. **14일 연속**으로 12명 이상이 참여 상태여야 해요(중간에 빠지면 다시 세는 경우가 있어요). 그동안 Claude가 고친 버전을 올려도 괜찮아요.
3. 대시보드의 **「프로덕션 액세스 신청」** → 테스트가 어땠는지, 어떤 의견을 받아 무엇을 고쳤는지, 출시 준비가 되었다고 보는 이유 같은 질문에 답해요. 승인되면 A처럼 출시해요.

## 10. 앞으로 업데이트

1. Claude가 새 버전 AAB를 만들어 드려요(버전 번호 +1, 같은 업로드 키로 서명).
2. 내부 테스트에 먼저 올려 휴대폰에서 확인 → 프로덕션으로 승격.
3. 출시 노트는 그 버전에서 바뀐 것만 짧게. 그림이나 기능이 많이 바뀌면 스크린샷도 새로 찍어 드려요(`tools/store_shots.mjs`).
