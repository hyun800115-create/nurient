# 「행복한 눈꽃마을 이야기」 Unity 전환 + GitHub 팀 협업 작업 계획 (초안)

작성 2026-11-21 · 대표님 검토용 · 숫자는 코드와 이전 조사(2026-11-07)에서 센 값이에요.

## 0. 결론

- **Unity 전환은 다시 만드는 일이에요.** 지금 게임은 JavaScript(Phaser)로 되어 있어요. Unity는 C#을 써요. 그래서 출시에 들어가는 코드 약 6만 줄을 전부 새로 짜야 해요. AI 작업 기준으로 **약 2~3개월**이 걸려요. 예상이 ±50%쯤 틀릴 수 있어요.
- **팀 협업은 Unity 없이도 오늘 시작할 수 있어요.** GitHub 비공개 저장소, 작업 규칙, 할 일 보드는 지금 게임에도 그대로 써요.
- **추천 순서**

  | 순서 | 할 일 | 기간 |
  |---|---|---|
  | ① | GitHub 팀 작업 환경 만들기 | 1주 |
  | ② | 지금 버전 v4.3(b1)을 마무리하고 Play 출시 유지 | 진행 중 |
  | ③ | Unity **시험판**: 핵심 한 장면만 만들어 느낌·성능·저장 이전을 확인 | 2~3주 |
  | ④ | 대표님이 폰으로 보고 계속할지 결정 | — |
  | ⑤ | 본 전환 | 6~8주 |
  | ⑥ | 같은 앱의 업데이트로 Play 버전 교체 | — |

- **Unity로 얻는 것**
  - Unity를 아는 팀원을 구하기 쉬워요.
  - 기획자가 에디터에서 수치를 직접 고칠 수 있어요.
  - 아이폰·PC로도 낼 수 있어요.
  - 광고·결제 패키지가 기본으로 있어요.
  - 저사양 폰에서 더 안정적일 수 있어요.

## 3. GitHub 팀 협업 준비 (1주차)

이 단계는 Unity와 상관없이 지금 바로 할 수 있어요.

### 3-1. 계정과 권한

| 권한 | 누구 |
|---|---|
| 관리자 | 대표님 |
| 쓰기 | 개발자, 아트 담당 |
| 읽기 | 테스터 |

- 조직을 만들고 팀원을 초대해요.
- Claude가 쓰는 GitHub 연결도 새 저장소에 권한을 줘야 해요.

### 3-2. 작업 흐름

- `main`: 언제나 실행되는 버전이에요. 직접 올리지 못하게 막아요.
- 기능 하나마다 `feature/기능이름` 가지를 만들어 작업해요.
- 작업이 끝나면 PR(검토 요청)을 올려요. **1명 승인 + 자동 빌드 통과** 뒤에 `main`에 합쳐요.
- 출시할 때는 `v5.0.0` 같은 태그를 붙여요.
- 화면이 바뀌는 PR은 대표님 승인을 꼭 받아요.

### 3-3. 큰 파일 (Git LFS)

- 그림·소리·폰트·Blender 파일(png, psd, blend, wav, mp3, ogg, fbx, ttf 등)은 LFS로 따로 보관해요.
- 무료 범위

  | 계정 | 저장 | 내려받기 |
  |---|---|---|
  | 무료 | 10 GB | 월 10 GB |
  | 팀 플랜 | 250 GB | 월 250 GB |

  지금 그림이 0.2 GB라 소규모 팀이면 무료 범위로 충분해요.
- **요금 한도를 0원으로 설정**해서 예상 못 한 요금을 막아요.
- 그림 파일은 **잠금(lock)** 기능을 써요. 두 사람이 같은 그림을 동시에 고치는 충돌을 막아 줘요.

### 3-4. Unity 전용 설정

- `.gitignore`: `Library`, `Temp`, `Logs`, `Build`, `UserSettings`는 올리지 않아요.
- 에셋 저장 방식은 **Force Text**, 메타 파일은 **Visible Meta Files**로 해요. 그래야 GitHub에서 바뀐 곳이 보여요.
- **UnityYAMLMerge**(스마트 병합)를 켜요. 씬·프리팹이 겹쳐 고쳐졌을 때 자동으로 합쳐 줘요.

### 3-5. 비밀 지키기 (지금 규칙 그대로)

- Play 업로드 키, 테스트 키는 **저장소에 절대 넣지 않아요.**
  - 대표님이 따로 보관하시거나, GitHub Secrets에 넣어요.
- 관리자 비밀번호는 지금처럼 **암호화된 값만** 코드에 넣어요.
- 올리기 전에 자동 검사를 돌려요. 비밀번호·키·개인정보가 들어갔는지 GitHub Actions가 검사해요.

### 3-6. 일 관리

- **Issues**: 할 일 카드예요.
  - 기획 아이디어도 카드로 올려요.
  - 라벨은 기획 / 아트 / 버그 / 밸런스 / 출시로 나눠요.
- **Projects 보드**: 할 일 → 진행 중 → 검토 → 완료 순서로 카드를 옮겨요.
- **마일스톤**: 아래 5장의 단계마다 하나씩 만들어요.

### 3-7. 문서

| 문서 | 내용 |
|---|---|
| `README` | 설치하는 법, 프로젝트 여는 법 |
| `CONTRIBUTING` | 작업 규칙 |
| `docs/기획서` | 지금 기획서들을 옮겨 와요 |
| `CLAUDE.md` | AI 작업 규칙 |

### 3-8. 기존 `nurient` 저장소

- 지금은 공개라서 코드가 다 보여요. 비공개로 돌릴지 대표님이 정해 주세요.
- 비공개로 돌리기 전에 확인할 것: 개인정보처리방침 페이지 주소가 이 저장소에 걸려 있지 않은지요. 방침 페이지는 따로 작은 공개 저장소에 올리는 계획이 이미 있어요.

## 4. Unity 프로젝트 구성

### 4-1. 버전과 비용

- **Unity 6.3 LTS**를 써요. 2027년 12월까지 지원돼요. 팀 전원이 같은 버전을 써요.
- 2D URP 템플릿으로 시작해요.
- 비용

  | 플랜 | 조건과 비용 |
  |---|---|
  | Unity Personal | 무료. 최근 1년 매출·투자가 20만 달러 이하일 때 |
  | Unity Pro | 1인당 연 약 2,310달러. 20만 달러를 넘으면 필요해요 |

- Unity 6부터는 무료판에서도 시작 로고를 끌 수 있어요.

### 4-2. 폴더 구조

```
Assets/_Snowbloom/
  Scripts/
    Core/        카메라·조이스틱·아이소 좌표·사운드
    Data/        밸런스·아이템·건물 표 (ScriptableObject)
    Systems/     경제·마을·길찾기·목표·튜토리얼·순위
    Entities/    건물·작업대·주민·차량
    UI/          HUD·창·관리자 패널
    Save/        저장·불러오기·옛 저장 변환
  Art/           Atlases · Buildings · Characters · Props · UI · Title
  Audio/
  Prefabs/
  Scenes/        Boot · Title · Village
  Localization/  한국어 · 영어 표
  Tests/         EditMode · PlayMode
Packages/        (올려요)
ProjectSettings/ (올려요)
Library/         (올리지 않아요)
```

### 4-3. 지금 기술을 Unity에서 어떻게 바꾸나

| 지금 (Phaser) | Unity에서 |
|---|---|
| 그리기 순서: 소수점 깊이 값을 518곳에서 지정 | Sorting Group + 아이소 Y정렬로 다시 설계 |
| 건물 뒤에 가면 건물이 투명해지는 기능 | 같은 기능을 셰이더로 다시 만들기 |
| 그림 묶음: Phaser용 JSON 281개 + 자체 형식 65개 | 자동 가져오기 도구(에디터 스크립트)를 만들어 Unity Sprite Atlas로 변환 |
| 큰 그림을 필요할 때만 불러오기 | Addressables |
| 물: 웹 셰이더 3개 | Shader Graph |
| 글자와 한/영 문장 | TextMeshPro + 한글 폰트, Localization 패키지 |
| 밸런스 숫자가 코드 안에 있음 | **ScriptableObject.** 기획자가 에디터에서 숫자를 직접 고쳐요 |
| 움직임 효과(트윈) 230곳, 카메라 확대 | DOTween 같은 도구로 하나씩 옮기기 |
| 저장: JSON | **같은 JSON 구조를 유지.** 옛 저장을 옮기기 쉬워요 |
| 웹 화면 앱 껍데기 | Unity 안드로이드 빌드 |

- 씬 하나는 한 번에 한 사람만 고쳐요. 작업은 주로 **프리팹 단위로 나눠서** 해요. 팀 작업 충돌을 크게 줄여 줘요.

AI 작업 기준이고, ±50% 틀릴 수 있어요.

| 단계 | 기간 | 내용 | 끝났다는 기준 |
|---|---|---|---|
| 0. 준비 | 1주 | GitHub 조직·저장소·규칙. Unity 설치 PC. Claude Code 연결. 빈 프로젝트 빌드 | 빈 앱이 폰에 설치됨 |

| 4. 진행과 화면 | 2주 | HUD, 목표·튜토리얼, 순위(촌장 → 읍장), 관리자 패널, 타이틀, 주민 대화·눈꽃말 | 처음부터 물류창고 다음 목표까지 끝까지 플레이 가능 |
| 5. 출시 준비 | 1주 | 같은 패키지 이름, 같은 업로드 키, 버전 번호 5000번대, Android API 36, 옛 저장 자동 이전, 비공개 테스트 | 테스터 63명의 마을이 그대로 이어짐 |

| **합계** | **약 10~14주 (2.5~3.5개월)** | | |

- 시험판에서 중단하기로 하면 잃는 건 2~4주예요. Phaser 판은 그대로 살아 있어요.

다른 엔진(Godot 등)도 이전에 검토했어요. 팀원 구하기, 자료 양, 광고·결제 패키지를 생각하면 Unity를 그대로 추천해요.

## 8. 이 계획을 정하시면 바로 할 일
